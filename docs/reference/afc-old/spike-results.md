## Follow-ups
- **Task 12 (`fly`, plan lines ~3662-3672), from S6:** `fly` launches `claude` with only `--add-dir`, which is the default permission mode. In that mode, edits to the code folder are denied non-interactively, and an interactive user gets a prompt. Decision needed before implementing: either add `--permission-mode acceptEdits` to the `cliArgs` (the PreToolUse scope guard still runs first and can deny), or keep the default and add `Edit(<code>/**)` / `Write(<code>/**)` allow rules. Task 18's eval runner (plan line ~5633) already uses `--permission-mode acceptEdits`.
- **Task 15 (brain text, plan line ~4602, "Claude Code notes"), from S3:** the user-facing commands must be written with the plugin prefix (`/flight-control:approve`, `/flight-control:drop`, `/flight-control:override`). The bare `/approve` is not a registered command. The text already says the prefixed form is the same command; the change makes the prefixed form the one documented.
- **Task 12 (`isPluginInstalled` test, plan line ~3499), from S2:** the real shape is an array of `{id, enabled, ...}` with no `name` field. The id-based cases (plan lines ~3498 and ~3500-3502) match it. The `{"plugins":[{"name":...}]}` case is not a shape the CLI emits; it can be dropped. Not a design change.
- **Task 5, Task 13, Task 14:** no change. S5 confirms the regex against the raw prefixed prompt. S7 confirms SessionStart injection. S4 confirms PreToolUse covers subagents (`agent_id` available).
- **Task 13/14 (latency, from S9):** re-run the S9 timing on the real `afc hook` bundle once it exists. Only the stub was measured here.
- **Manual checks still open:** the `/memory` listing (S1) and the interactive `/` autocomplete for the command name (S3). Neither changes a decision above.
