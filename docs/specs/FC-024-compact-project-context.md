# FC-024 — Compact project context

Size: M · Status: next · Started: - · Done: -

Asked for on 2026-10-25, to give sessions a short, fresh summary of the active project without
re-reading the full plan tree each turn.

## Goal

The active project workspace holds a prebuilt compact context file, regenerated by the CLI from plan,
spec status, architecture notes and registry fields, so session start can inject kilobytes instead
of tens of kilobytes of plan files.

## You'll know it works when

- `sh bin/afc context refresh` writes or updates `context.compact.md` (name fixed in Decisions) under
  the active project workspace with sections for project id, code path, mode, next slice, open spec
  statuses, and the last few `decisions.md` lines (cap documented, e.g. 2 KB total).
- `sh bin/afc context show` prints the file path and byte size, or a clear message when missing.
- Session start (or `afc-start` skill text after this ships) tells the co-pilot to read only the
  compact file for orientation unless the user asks for the full plan.
- Refresh runs automatically after `slice record`, `deliver`, `plan` compaction, and project switch
  when cheap; manual refresh always works.
- Refresh refuses without an active project; it never writes into the app repo, only the workspace.
- Tests build a fixture workspace and assert section content and size cap.

## Out of scope

Summarizing the entire codebase (architecture skill still does deep reads). LLM-generated summaries;
the file is deterministic template text. Cross-project indexes (`registry.json` stays separate).
Trimming skills (`FC-020`).

## Design notes

- **Source files.** Read `plan/master-plan.md` or project plan table, active spec headers, slice
  checkboxes for `next`, `plan/architecture.md` first paragraph, `plan/decisions.md` tail — all via
  existing Python plan helpers where possible.
- **Stale marker.** First line includes `Refreshed: <iso>` so humans know when to re-run refresh.
- **Hooks.** Optional SessionStart injection of the compact path in additionalContext; keep under
  hook size limits — if too large, inject only the path and one-line summary.
- **Drift.** If compact file missing at session start, hook says "run context refresh" once, does not
  fail the session.

## Slices

- [ ] 1. Builder function — you'll check it by `tests/test_context_compact.py`: fixture plan tree
      produces expected sections and respects the byte cap (tests)
- [ ] 2. `context refresh` and `context show` — you'll check it by CLI tests on a temp workspace
      (tests)
- [ ] 3. Auto-refresh hooks — you'll check it by tests that `slice record` and project switch call
      refresh (mock filesystem) or integration with one command
- [ ] 4. Session start pointer — you'll check it by `afc-start` (or session hook) naming the compact
      file and not listing every plan file; content test on the skill/hook text
